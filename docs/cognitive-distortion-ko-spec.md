# 작업 지시서: 인지 왜곡 진단 테스트 한국어 사이트 제작

## 0. 개요
- **목표**: 인지 왜곡 자가진단 테스트(30문항, 10개 유형)를 한국어 웹사이트로 만든다.
- **참고 원본**: https://commutest.com/cognitive-distortion/ (일본어), 영어판 https://commstyle.com/cognitive-distortion/
- **원칙**: 원본 사이트의 **구조와 흐름만 참고**한다. 원본의 문항, 이미지, 로고, 디자인, 안내 문구, 결과 해설, 칼럼 글은 **복사하거나 번역하지 않는다**. 문항은 이 문서의 자체 문항(섹션 3-2)만 쓰고, 결과 해설과 칼럼은 이 문서의 기준에 따라 새로 작성한다. 원본 페이지 텍스트를 가져와 참고하지 않는다.
- **작업 위치**: 현재 워크스페이스 루트에 프로젝트를 만든다.

## 1. 기술 스택
- 순수 정적 사이트: HTML + CSS + Vanilla JS. 빌드 도구와 프레임워크는 쓰지 않는다.
- 서버와 DB는 쓰지 않는다. 점수 계산과 결과 표시는 모두 클라이언트에서 처리한다.
- 응답 데이터를 외부로 전송하지 않는다. 저장이 필요하면 `localStorage`에 둔다. 저장은 선택 사항이며, 접근할 때는 try/catch로 감싼다.
- GitHub Pages, Netlify, Vercel 중 어디에 올려도 그대로 동작해야 한다.
- 폰트는 Pretendard를 쓴다. CDN 사용 가능.

### 폴더 구조
```
/
├─ index.html          # 테스트 소개 (랜딩)
├─ test.html           # 문항 페이지
├─ result.html         # 결과 페이지
├─ articles/           # 칼럼 6편 (2차 작업, 섹션 6 참고)
├─ assets/
│  ├─ css/style.css
│  └─ js/
│     ├─ data.js       # 문항, 유형, 해설 데이터 (텍스트는 전부 여기에 둔다)
│     ├─ test.js
│     └─ result.js
└─ README.md
```
문항, 유형 설명, 결과 해설은 **모두 `data.js` 한 곳에** 객체로 둔다. HTML에 하드코딩하지 않는다. 문구 수정은 `data.js`만 고치면 되게 한다.

## 2. 페이지 구성

### 2-1. index.html (소개)
1. 상단 내비게이션: 홈, 테스트 목록(지금은 비활성), 소개
2. 브레드크럼: 홈 > 테스트 목록 > 인지 왜곡 진단
3. 타이틀: **인지 왜곡 진단 테스트**
4. "인지 왜곡이란?" 설명 문단 (섹션 3-1)
5. 10가지 유형 카드 (번호 ①~⑩, 이름, 한 줄 설명)
6. 안내 박스: 의학적 진단이 아니라는 고지와 전문가 상담 권유 (섹션 3-4)
7. **[진단 시작하기]** 버튼 → `test.html`
8. 칼럼 목록 6개 (2차 작업 전에는 "준비 중"으로 표시)
9. 접이식(`<details>`) **"테스트 개발 방법"**: 이론 배경, 문항, 채점 기준, 한계, 참고문헌
10. 푸터: 이용약관, 개인정보처리방침, 운영자 정보 (자리만 만들어 둔다)

### 2-2. test.html (문항)
- 안내 문구: "최근 몇 달 동안의 나를 떠올리며, 처음 떠오르는 느낌대로 골라 주세요."
- 30문항을 한 페이지에 순서대로 보여준다. 문항 번호를 함께 표시한다.
- 문항마다 5점 응답을 받는다.
  - 원 버튼 5개를 가로로 배치하고, 왼쪽 끝에 "전혀 아니다", 오른쪽 끝에 "매우 그렇다" 라벨을 단다.
  - 버튼 크기는 양 끝이 크고 가운데로 갈수록 작게 한다.
  - 점수 매핑은 왼쪽부터 0, 1, 2, 3, 4.
  - ⚠️ 원본은 왼쪽이 "그렇다"이지만, **이 사이트는 왼쪽이 "아니다"인 방향으로 통일**한다.
- 답을 고르면 다음 문항으로 부드럽게 스크롤한다.
- 상단에 고정된 진행률 바를 둔다 (예: 12 / 30).
- 하단 [결과 보기 전에] 박스:
  - 이 테스트는 병원 진단을 대신하지 않아요
  - 답변은 이 기기 안에서만 계산되고 어디에도 저장·전송되지 않아요
  - 그날의 컨디션에 따라 결과가 달라질 수 있어요
  - 점수는 '나'를 정의하는 게 아니라 생각 습관을 살펴보는 출발점이에요
- **[동의하고 결과 보기]** 버튼
  - 미응답 문항이 있으면 버튼을 비활성화하거나, 첫 미응답 문항으로 스크롤하고 강조 표시한다.
  - 30문항을 모두 답하면 응답 배열을 `result.html`로 넘긴다. URL 쿼리 `?a=01234...`(30자리 숫자) 형식을 쓴다. 결과 링크를 공유할 수 있게 하기 위해서다.

### 2-3. result.html (결과)
- 쿼리 `a`를 파싱한다. 형식이 잘못되었으면 "다시 검사하기" 안내를 띄운다.
- 표시 순서:
  1. **종합 점수** (0~120)와 등급 문구
  2. **10개 유형 레이더 차트**. Chart.js를 CDN으로 쓰되, 버전을 고정한다(예: `chart.js@4.4.1`). 축 범위는 0~12.
  3. **유형별 가로 막대**: 점수와 강함·보통·약함 배지. 점수가 높은 순으로 정렬한다.
  4. **상위 1~3개 유형 상세 해설**: 점수 7점 이상인 유형만 보여준다. 해당 유형이 없으면 "전반적으로 유연한 사고" 메시지를 띄운다.
  5. 나머지 유형은 접이식으로 해설을 보여준다.
  6. 고지 박스: 의학적 진단 아님, 전문가 상담 권유. 상담 연락처를 함께 적는다 (섹션 3-4).
  7. 버튼: [다시 검사하기], [결과 링크 복사], [공유하기] (`navigator.share`를 지원하면 사용)

## 3. 콘텐츠

### 3-1. 인지 왜곡이란?
> 같은 일을 겪어도 누군가는 금방 털어내고, 누군가는 오래 괴로워해요. 차이를 만드는 건 사건보다 그 사건을 해석하는 방식인 경우가 많아요. 인지 왜곡은 상황을 필요 이상으로 어둡게 읽게 만드는 생각의 지름길이에요. 누구에게나 조금씩 있지만, 자주 쓰이면 마음을 지치게 하고 관계를 어렵게 만들 수 있어요. 이 테스트로 내가 자주 빠지는 생각 습관을 10가지 유형으로 살펴보세요.

### 3-2. 10가지 유형과 30문항
`data.js`에는 아래 구조로 넣는다.
```js
{ id: 1, key: "allOrNothing", name: "흑백논리", desc: "...", items: [1,2,3] }
```

| # | 유형 | 한 줄 설명 | 문항 |
|---|---|---|---|
| ① | 흑백논리 | 성공 아니면 실패, 둘 중 하나로만 본다. | 1–3 |
| ② | 과잉일반화 | 몇 번의 경험을 '언제나', '절대'로 넓혀 버린다. | 4–6 |
| ③ | 정신적 여과 | 여러 장면 중 마음 아픈 한 장면만 크게 남긴다. | 7–9 |
| ④ | 긍정 격하 | 잘한 일도 '쳐주지 않는' 이유를 찾아낸다. | 10–12 |
| ⑤ | 독심술 | 확인하지 않은 남의 속마음을 나쁜 쪽으로 짐작한다. | 13–15 |
| ⑥ | 확대·축소 | 걱정과 단점은 키우고 성과와 장점은 줄인다. | 16–18 |
| ⑦ | 감정적 추론 | 지금 드는 기분을 사실의 증거로 삼는다. | 19–21 |
| ⑧ | 당위 진술 | '~해야만 해'라는 규칙으로 나와 남을 다그친다. | 22–24 |
| ⑨ | 낙인찍기 | 한 번의 행동으로 사람 전체에 이름표를 붙인다. | 25–27 |
| ⑩ | 개인화 | 여러 원인이 있는 일도 내 책임으로 끌어온다. | 28–30 |

**문항** (자체 제작, 모두 정방향 채점)
> 이 문항은 원본 사이트의 문항을 번역하거나 다듬은 것이 아니라 Burns의 10가지 분류 개념만 바탕으로 새로 쓴 것이다. Antigravity는 문항 문구를 원본에 가깝게 고치지 않는다.

① 흑백논리
1. 계획이 하나라도 틀어지면 그날 하루를 통째로 망친 것처럼 느껴진다.
2. 사람을 '내 편'과 '아닌 사람'으로 나눠서 보게 된다.
3. 100점이 아니면 80점이나 0점이나 별 차이가 없다고 느낀다.

② 과잉일반화
4. 면접이나 시험을 한 번 망치면 다음에도 똑같이 될 거라고 확신한다.
5. 연락이 한두 번 늦어지면 "사람들은 결국 다 떠난다"는 생각이 든다.
6. 비슷한 실수를 두 번 하면 "나는 원래 이런 사람"이라고 결론 내린다.

③ 정신적 여과
7. 발표가 끝나면 잘한 부분보다 버벅인 한 순간이 계속 떠오른다.
8. 좋은 피드백 열 개보다 지적 한 개가 하루 종일 마음에 남는다.
9. 하루를 돌아보면 기분 상했던 장면부터 먼저 생각난다.

④ 긍정 격하
10. 일이 잘 풀리면 "이번엔 문제가 쉬웠을 뿐"이라고 생각한다.
11. 누가 고맙다고 하면 "별거 아닌데"라며 바로 깎아내린다.
12. 내가 이룬 성과를 남에게 말할 만한 일로 여기지 않는다.

⑤ 독심술
13. 회의 중 누가 한숨을 쉬면 내 의견이 마음에 안 들어서라고 생각한다.
14. 메시지에 답장이 짧으면 상대가 나에게 화가 났다고 짐작한다.
15. 사람들이 속으로는 나를 한심하게 볼 거라는 생각이 든다.

⑥ 확대·축소
16. 작은 실수 하나 때문에 일이 크게 잘못될 거라며 걱정이 커진다.
17. 칭찬받은 일은 금방 잊지만 지적받은 일은 오래 곱씹는다.
18. 내 장점은 누구나 가진 평범한 것이라고 여긴다.

⑦ 감정적 추론
19. 마음이 불안하면 실제로 위험한 상황이라고 믿게 된다.
20. 내가 부족하다고 느껴지는 날에는 정말 부족한 사람이라고 생각한다.
21. 죄책감이 들면 내가 분명 뭔가 잘못했을 거라고 여긴다.

⑧ 당위 진술
22. 어른이라면 힘든 티를 내면 안 된다고 생각한다.
23. 쉬는 날에도 뭔가 생산적인 일을 해야 마음이 놓인다.
24. 사람들이 '당연히' 지켜야 할 것을 안 지키면 화가 많이 난다.

⑨ 낙인찍기
25. 실수를 하면 속으로 나 자신을 "바보", "한심이" 같은 말로 부른다.
26. 한 번 무례했던 사람은 '그런 사람'이라고 정해 버린다.
27. 한 가지 일을 못 해내면 나라는 사람 전체가 별로라고 느낀다.

⑩ 개인화
28. 팀 프로젝트가 잘 안되면 내가 더 잘했어야 했다고 자책한다.
29. 모임 분위기가 가라앉으면 내가 무슨 말을 잘못했는지 되짚어 본다.
30. 가족이나 친구가 힘들어하면 내가 뭔가 놓친 탓이라고 느낀다.

### 3-3. 채점 기준
- 응답: 전혀 아니다 0 / 별로 아니다 1 / 보통이다 2 / 약간 그렇다 3 / 매우 그렇다 4
- **유형 점수** = 해당 3문항의 합 (0~12)
  - 10~12 **강함** / 7~9 **보통** / 0~6 **약함**
- **종합 점수** = 30문항의 합 (0~120)
  - 96~120 인지 왜곡 경향 **매우 강함**
  - 71~95 **다소 강함**
  - 46~70 **약간 있음**
  - 0~45 **거의 없음**
- 채점 로직은 순수 함수로 분리한다: `scoreByType(answers)`, `totalScore(answers)`, `level(score)`. 경계값(6/7, 9/10, 45/46, 70/71, 95/96)에 대한 간단한 테스트 코드도 둔다.

### 3-4. 결과 해설 작성 기준 (새로 작성)
유형마다 아래 항목을 **한국어로 직접 작성**한다. 원본 해설을 번역하지 않는다.
- `summary`: 이 경향이 강할 때 나타나는 모습 (2~3문장)
- `examples`: 일상에서 흔히 하는 생각의 예시 2~3개 (직장, 연애, 가족 상황 등)
- `impact`: 감정과 관계에 미치는 영향 (2~3문장)
- `tips`: CBT에 기반한 실천 팁 3개 (증거 찾기, 대안적 사고, 회색 지대 찾기 등 구체적인 행동으로)
- 분량은 유형당 600~900자. 단정하거나 겁주지 않는 따뜻한 말투, 존댓말(~해요체)로 쓴다.
- 레벨별(강함/보통/약함) 도입 문장은 따로 1문장씩 둔다.

**종합 등급 문구** (예시이며 다듬어도 된다)
- 매우 강함: "부정적인 해석 습관이 여러 영역에 걸쳐 강하게 나타나요. 혼자 감당하기 버겁다면 전문가와 이야기해 보는 것을 권해요."
- 다소 강함: "몇몇 사고 패턴이 일상에 영향을 주고 있을 수 있어요. 높게 나온 유형부터 살펴보세요."
- 약간 있음: "누구에게나 있는 수준의 사고 습관이에요. 스트레스가 클 때 두드러질 수 있어요."
- 거의 없음: "비교적 유연하고 균형 잡힌 시각으로 상황을 바라보고 있어요."

**고지 문구** (소개 페이지와 결과 페이지에 공통으로 넣는다)
> 이 테스트는 의학적 진단이 아니며, 통계적 신뢰도·타당도 검증을 거치지 않은 자기 이해용 도구입니다. 일상생활에 지장을 줄 만큼 힘들다면 정신건강의학과 전문의나 상담 전문가와 상담해 보세요.

## 4. 디자인
- 차분하고 신뢰감 있는 톤. 메인 컬러는 딥 블루나 틸 계열 1개, 배경은 밝은 웜그레이.
- 원본 사이트의 이미지와 로고는 쓰지 않는다. 아이콘은 SVG로 직접 만들거나 Lucide 같은 오픈 라이선스 아이콘을 쓴다.
- **모바일 우선**. 360px 폭에서 가로 스크롤이 없어야 한다. 콘텐츠 최대 폭은 720px.
- 응답 버튼의 터치 영역은 최소 44px.

## 7. "테스트 개발 방법" 섹션 (index.html 접이식)
- **이론 배경**: Aaron Beck의 인지치료(1970년대)와 David Burns의 10가지 인지 왜곡 분류를 자체 문장으로 소개한다. Burns의 '결론 비약'은 이 테스트에서 '독심술' 측면만 측정한다고 적는다.
- **문항 구성**: 유형당 3문항, 총 30문항. 일상 장면(직장, 학교, 연락, 모임, 가족)을 구체적으로 묘사하는 방식으로 자체 개발했다.
- **채점 기준**: 섹션 3-3 표를 그대로 넣는다.
- **한계**: 요인분석, 신뢰도·타당도 검증을 하지 않았으며 학술 연구용이 아니다.
- **참고문헌**
  1. Beck, A. T. (1976). *Cognitive Therapy and the Emotional Disorders.*
  2. Burns, D. D. (1980). *Feeling Good: The New Mood Therapy.*
  3. Özdel, K. et al. (2014). Cognitive Distortions Scale (CDS): Reliability and validity study. *PLoS ONE*, 9(8): e105956.
- 감수자와 개발자 정보는 `[감수자 정보 입력]` 자리로만 남긴다. 원본 개발자 이름을 넣지 않는다.
